# Original domain-pack decimal capability

The exact original UMF 0.8 commerce, supply-chain, archaeology and ecology models
use decimal(18,2). The checksum-verified public Truss 0.0.16 wheel still admits
only decimal(18,4) in its selected closed source profile. Source inspection also
shows unavailable inventory is rejected before catalog registration. Unknown
extensions can remain opaque when required fields are supported; unsupported
known numeric facets do not use that path. No native attempt was run.

Truss Impl received the capability request under the user's standing messaging
authorization. The implementation must preserve original facets and tokens through
acceptance, create/update, read, receipt replay and feed. Decimal(18,2) permits
sixteen whole digits: 9999999999999999.99 is valid, while excess declared precision
or scale must refuse. Relabeling to 18,4 would narrow that whole-number range.

After a published capability is available, run one tiny original pack through the
public source and Delta workflow before extending other representatives. Their
remaining constructs require separate admission. The retained source inspection
is an upstream gap, not native acceptance evidence or completion of P08/P10.
