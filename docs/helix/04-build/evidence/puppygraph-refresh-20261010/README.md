# Immutable PuppyGraph release refresh

The reusable host owner and public adapter activate independently admitted release-specific labels and carriers, verify complete original graph values and incident identities, and retain the prior release through successor staging. Supplied source/native policy remains mandatory; hashes establish byte correspondence rather than authority.

The retained G run uses the existing cached PuppyGraph 1.13.0 ARM64 image, two tiny DuckDB 1.5.6 VARCHAR carriers, Neo4j client 5.28.2, two CPUs and 3 GiB locally. It observes R1 (3 nodes, 3 edges), a rejected native schema request, an actual original R2 node-only upload followed by controlled cancellation, unchanged R1, and completed R2 (3 nodes, 4 edges). Resumption uses identical original request bytes; completed replay performs no POST. Fresh owners reopen explicit original handles and verify full values, native edge identity and endpoints.

Selection is process-local. This evidence does not establish a durable latest alias, an installed CLI activation workflow, Unity Catalog access, source ingestion or protected ACK. The interruption is a controlled partial native POST, not a lost response from the complete POST. Native generation is not bound by the handle; actual schema bytes and concrete engine instance are renewed.

`native-g.tar.gz` contains exact native observations and current imported project source snapshots, plus preserved failed A/B/D/E/F diagnostics and the unexecuted C recipe. Runtime, database and executable products are represented by hash vectors only. `native-g-inventory.json` maps every archive member to original bytes. `native-g-result-freeze.json` and `source-g-freeze.json` pin the qualified result and source scope.
