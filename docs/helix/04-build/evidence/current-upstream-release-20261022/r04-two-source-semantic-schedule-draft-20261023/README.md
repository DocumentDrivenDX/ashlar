# R04 current-core two-source semantic schedule draft

This is an exploratory semantic draft only, not an authoritative current-core R04 schedule. Person/Place types, fields, presence expectations and lifecycle transitions below are illustrative candidates; none may be frozen or used as source/request expectations until both A and B actual UMF 0.10 sources are accepted, their complete model/report/view pins are reviewed, and the selected semantics are reconciled against those sources. This draft is deliberately not frozen: the canonical schedule digest, accepted A/B source IDs, request bytes, provider-assigned IDs, feed pages, cursors, writer positions, event inventories and publication vectors are null. Its file checksums are archival checksums, not a schedule identity.

The draft illustrates the required global order `A1, B1, A2, B2, A3, B3, A4, B4`, and a possible same-entity R1/R2/R3 lineage. It separates A/B authority and demonstrates source-qualified object, edge and endpoint identity. The current UMF 0.10 Person/Place example is only a vocabulary witness, not accepted R04 source evidence or a selected R04 model. All domain types, field semantics, values and expected transitions remain exploratory and must be replaced or explicitly re-admitted after both sources are accepted. A4/B4 remain additive-candidate placeholders pending the exact independently accepted model/extension.

The independent prefix oracle now starts from independently pinned complete A/B baseline bags and progress; prefix zero does not assert an empty graph. Later prefixes are the baseline plus only completed R04 deltas. It separates publication-manifest progress from protected source ACK checkpoints and leaves R3 incident-edge closure unresolved until one policy is fixed before schedule freeze. It requires full vectors, exact presence/value bags, edge identity/endpoints, history, tombstones, schema revisions and source-specific ACK only after independent durable verification. It does not derive expectations from SQL or native output. The closing-evidence register separately requires exact replay/no-extra-commit, fresh-process journal restart, uncertain/missing-journal refusal, breaking-evolution refusal, a positive retained read within the retention interval, and a separate expired-version negative refusal.

In particular R03 A migration/resume, genesis publication/ACK and seed readback are not complete, and independent B acceptance/installation/feed/consumer/ACK custody is absent.
