# R04 B-source installation packet (inert draft)

Status: review draft only. No PostgreSQL, Spark, source registration, catalog acceptance, feed read, destination receipt, ACK, or cleanup was performed. This packet does not authorize execution. Every B identity and source pin remains unset; the R04 schedule is still unfrozen.

## Purpose and boundary

Prepare a distinct local Truss 0.0.49 / UMF core 0.10.0 B installation for the R04 eight-slot schedule. B must have independently accepted source bytes, catalog revision/report/view, provider-assigned installation and source identities, source epoch/namespace, consumer registration, feed, and protected destination receipt scope. B must not reuse, relabel, re-register, or advance A's consumer or ACK. A's current retained Truss 0.0.48 migration/resume and pending R03 genesis/ACK/seed readback are separate dependencies and remain untouched.

The public installation boundary in the current Truss package is experimental and does not provision authority on behalf of the caller. Its API can prepare/accept catalogs and install a local catalog runtime, but it does not supply an accepted UMF source, accepted source IDs, a graph destination, or approval to execute. The package observation below came from the isolated r3 reviewed runtime tree; it is a machine-bound source snapshot, not an execution claim. The current adopted Truss package hash is recorded by the authoritative R3 packet at `../truss-049-lifecycle-ready/r3-review-packet-20261023/README.md` and committed readiness record at `../../../../current-upstream-release-20261023/truss049-r3-readiness-20261023/README.md`.

## Current Truss 0.0.49 public API observations

Read-only source inspection found these public entry points:

- `truss.LocalPostgres(data_directory)` is a one-use context manager. `__enter__` rejects a reused context, symlink data directory, a nonempty non-PG directory, wrong PostgreSQL major, existing `postmaster.pid`, or an active/leased directory; it creates an empty data directory with mode 0700 and initializes PostgreSQL when needed. `__exit__` calls `close()`. Re-entry/restart requires a new context. The API does not make an arbitrary path safe: the caller must first select a fresh, uniquely B-owned path and prove it is empty and disjoint from every A path.
- `CatalogReferenceAssembly.prepare_catalog(documents, source_version=...)` produces `PreparedAcceptance` before a source transaction. `accept_in_transaction(tx, prepared, request_key=..., origin_bytes=..., expected_revision=..., expected_documents=...)` uses that prepared object and caller transaction. A single complete accepted `CatalogRegistration` is not equivalent to a draft or preparation result.
- `install_in_transaction(tx, owner_role=..., registrar_role=...)` is an explicit install step. The selected owner and registrar/client names must be bound before the call; the installer creates those roles in the installation transaction and returns a pending installation result. Caller transaction commit is the settlement boundary. No role names are fixed here, and names from A must not be reused.
- `report_in_transaction(tx, revision=...)` and `catalog_view_in_transaction(tx, request)` expose accepted report and view observations; both exact results and canonical bytes/digests must be retained after acceptance.
- `register_feed_consumer_in_transaction(tx, consumer_id=..., reader_role=...)` registers a new ordinary consumer from genesis. It returns provider registration ID and genesis checkpoint. Consumer id, registration id, feed, epoch, and checkpoint are not predictable and must be captured from the accepted B instance.
- `read_feed_in_transaction(tx, consumer_id=..., maximum_facts=..., maximum_bytes=...)` reads the next whole transaction at that consumer's registered checkpoint. It has no arbitrary future-cursor argument and performs no ACK.
- `acknowledge_feed_with_receipt_in_transaction(tx, page, destination_id=..., request_sha256=..., publication_id=..., receipt_bytes=...)` binds a source-specific receipt to an exact page/request/destination/publication; settlement remains with caller commit. The method does not independently prove destination durability. Destination authority and receipt bytes must come from the actual protected B publication path.

Read-only source-file SHA-256 pins for this API inspection: `truss/__init__.py` `2b709459fa5e76c8ffa19d64609b5e2abc57cf5df275cd430fbbd2034025db44`; `truss/local_runtime.py` `7a0fce2fd418a3c239e7f6e847ac952d152d1967638251a4ebba2f5f29b90728`; `truss/catalog_runtime.py` `31c374621f6944f2b6bd03fb01e6a4331d0bb7bd20a5395eda718b4e677159d1`; `truss/feed.py` `0f5e5146368c254ea83b2d34229920a1b8bfa70fb3df000edaa7b7f5a820714c`; `truss/catalog_view.py` `167fc8fd2e304a9aaf9d485d957b0d124542617caa2f16c82f3d7aee42ec890c`; `truss/catalog_results.py` `a20fa3aba53fc6d4b867a818717b9ad0073430322cd7801854e6e89db9525465`; `truss/catalog_preparation.py` `fcbde90f084bd94ee05bf7e94d85c897258b2feff7ff0f2a16ee66253afaa5ea`. These are pins of the isolated reviewed installed source files, not additional package acceptance evidence.

The local runtime's PostgreSQL process is a real native effect and one-use context cleanup is not a rollback guarantee. A failure before any database transaction can be safely abandoned by closing the owned process and removing only a verified empty B-owned directory. Once initialization or any transaction may have occurred, preserve the complete data directory and logs; on uncertain commit, stop and reconcile the original request/readback. Never delete or recreate an uncertain/accepted installation as a retry. After B acceptance, retain the installation for the R04 feed and closing evidence; do not treat cleanup as permission to erase it.

## B-only bounded sequence proposed for future approval

This is a sequence proposal, not an executable runbook. B local source installation has no data dependency on A R03. This inert proposal could be considered for a separately authorized B-only window after the active Arras window is released, the exact B source bytes, UMF model and namespace are authored, independently qualified, and pinned for the acceptance attempt, B resource/path limits and custodians are approved, and Sol reviews the bounded packet. A R03 completion is a later R04 schedule-freeze and execution gate; it is not a B installation prerequisite.

1. Freeze the exact B UMF 0.10.0 source document bytes, document ID, source revision, origin bytes, expected catalog predecessor/document set, source SHA-256, and any required extension bytes. Confirm against a separately accepted UMF 0.10 installation/report that the document preserves unknown extensions, values, and presence semantics. No candidate fixture/example can stand in for this source.
2. Bind exact package lock/wheel hashes for Truss 0.0.49 and dependencies, UMF 0.10 core/tooling, Python/runtime, and catalog preparation result. Verify the selected package environment is isolated from A and record the exact `PreparedAcceptance` input/report evidence.
3. Select one B-owned unique root and fresh empty PGDATA path; record absolute paths and hashes in the pre-run approval. Prove no symlinks, no existing PGDATA, no alias to A, no active port/process, and no collision. Bind B to separate root, PGDATA, socket directory, port, process/lease namespace and retained evidence from A; prove no path, port, process, or database reuse. Freeze distinct B owner and registrar/client role names and the authorized installer/session binding before runtime installation. Bound the attempt to one local PostgreSQL initialization/start, one runtime install, one catalog acceptance request, one B consumer registration, and one clean shutdown; no automatic retry or path replacement.
4. In a single new `LocalPostgres` context over that approved B path, start the local server and establish the selected Truss host. Invoke `install_in_transaction` once with only the approved B owner and registrar/client names; Truss creates those roles as part of the install transaction. Commit once, then inspect installation release/layout and retain the provider-assigned installation identity. Any refusal/uncertainty stops the attempt and preserves evidence.
5. Using the exact prepared source and origin bytes, perform one catalog-acceptance transaction with the approved request key, expected catalog CAS pins, and explicitly approved B registrar/session authority supported by the installed profile. Commit once; capture provider-assigned source registration and revision. Read back the complete accepted report and complete catalog view; retain canonical bytes, digests, validation/source report, package pins, timestamps, and original response. If acceptance outcome is uncertain, reconcile this same request and original database state; do not submit a replacement request.
6. Bind and provision only the approved ordinary B reader role required for consumer registration, then register exactly one fresh B consumer from genesis using that B reader. Freeze a unique B consumer ID before the call; the provider returns the registration ID and genesis checkpoint. Capture the exact B feed, source epoch, source namespace, consumer ID, registration ID, genesis cursor and transaction inventory. Do not reuse A roles, read future R04 pages, or ACK during installation.
7. Close the owned Truss context once and confirm its owned server stopped. Retain accepted B PGDATA and all custody evidence. Do not clean it up: R04 requires this source installation to remain available. Cleanup is limited to incomplete, pre-acceptance, proven-empty B-owned directories after process-stop verification. An initialized or accepted directory is retained; uncertain status means retain and stop.
8. Before R04 execution, independently bind the protected destination ID, destination connection/authority, exact receipt scope, and expected ACK receipt schema to B. Do not use A's destination or ACK credentials/state. Schedule freeze must bind separate A/B installation, feed, epoch, consumer, and ACK identities and prove source-specific local-ID overlap from actual accepted evidence.

No native graph work or ACK belongs in this installation packet. A R03 status remains a schedule-freeze/execution prerequisite only; B install admission independently requires B source pins and isolated resources. Source ACK can advance only later, after the matching R04 slot's graph vector and independent oracle are durable and verified under CONTRACT-001/003.

## Unresolved pins and code/evidence gaps

All following values are currently unknown and intentionally `null` in the companion register: actual B source bytes and digest; accepted UMF 0.10 source version/document ID/revision/extension vocabulary; expected catalog predecessor; Truss provider acceptance revision/report/view bytes/digests; B registration and installation IDs; B source epoch/namespace; B feed, transaction inventory and consumer/registration/genesis cursor; B owner and registrar/client role names and session binding; ordinary B reader role/grant names; protected B destination ID and authority; destination receipt format and durable verification; B PGDATA/root paths, retention owner, resource bounds, and exact package/environment lock; B overlap witness against A local IDs; accepted incident-edge delete semantics required before R04 schedule freeze.

There is no independently accepted B model/report/view or B feed/epoch in the available R04 evidence. The current UMF 0.10 catalog example is a type/property vocabulary witness only. The selected R3 Truss runtime package evidence is not itself source acceptance. Existing A 0.48 source and consumer identities cannot satisfy B independence.

The present repository has no single governed tool/runbook that atomically enforces the proposed B lifecycle bounds, records the full provider responses, and distinguishes safe pre-acceptance cleanup from uncertain/accepted retention. The public APIs are composable transaction operations; caller-side custody, prebound B owner/registrar and reader role selection, directory ownership proof, commit certainty, and protected destination verification remain required controls. This is an evidence/control gap, not a request to extend Truss or mutate Ashlar source.
