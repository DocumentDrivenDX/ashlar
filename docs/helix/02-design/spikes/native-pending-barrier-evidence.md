# Atomic pending-publication barrier

2026-10-05; SPIKE-001 native private cooperative-publisher protocol test on unchanged dbw-aidev-cus warehouse. Four small catalog-managed tracked tables hold a fence/pending state, current data, durable receipt and manifest. Existing graph data and protocol are unchanged.

The data transaction validates epoch/owner plus no pending batch, conditionally writes the fence/pending row, changes one data carrier and commits a receipt. An independent session after restart observes pending r22-1. A later batch is rejected with publication pending; fence/data/receipt versions remain unchanged. This prevents the cooperating writer from overwriting the unresolved marker.

Recovery strictly resolves the pending carrier's non-null single row_commit_version and builds the descriptor from it. Publication writes the guard, inserts the descriptor and clears pending in one BEGIN ATOMIC. A deliberate SIGNAL after these writes rolls back both descriptor and clear: pending remains r22-1 and manifest remains empty. Valid publication inserts exactly one descriptor and clears pending. The next batch then succeeds; the old published pinned snapshot remains exact. The second synthetic batch is intentionally left pending as terminal fixture state, not an accepted release or background running process.

Harness `SPIKE-001-table-layout/native_pending_barrier.py`; native restart queries, rejected writes, unchanged versions, rollback/valid publication, old pinned carrier and terminal summary under `out/native/ashlar_pending_barrier_20261005_r22/`. This is one sequential protocol test, not concurrent next-batch contention, owner revocation/reassignment, lost responses, lease/permissions enforcement or full graph integration. A direct writer bypassing these guards is not prevented by table schema alone. Both data and publication phases must conditionally write the same guarded state; historical receipt/version validation remains mandatory.

The candidate now has scoped native evidence for strict actual-version resolution, physical maintenance metadata preservation and pending-publish isolation. Next integrate these primitives into repeated mixed-domain graph batches, using immutable batch receipts without guessed versions, counting resolver/barrier/descriptor work and measuring concurrent reads. No rate, caller latency, full-scale or external-engine admission follows from small protocol controls. Goal active; UMF deferred.
