# Fenced recovery descriptor publication

2026-10-05; SPIKE-001 bounded native experiment on unchanged dbw-aidev-cus warehouse.

A separate catalog-managed private manifest is guarded by a catalog-managed fence row. The transaction validates epoch/owner, conditionally increments the fence sequence (forcing a write conflict rather than relying on a read-only guard), inserts the fixed validated recovery receipt only when its publication ID is absent, then checks exactly one descriptor. Graph data and the ordinary original manifest are unchanged.

Two sessions synchronize after each observes an empty experimental manifest. One succeeds in **3.741s** caller duration; the other returns a terminal row conflict in **4.295s**. Exactly one descriptor exists and all recorded versions, source progress and revisions match the validated receipt. A fresh sequential recovery transaction changes only the fence sequence and leaves the manifest version unchanged. After explicit epoch/owner revocation, stale recovery SIGNALs before publication and leaves both fence and manifest versions unchanged. No automatic retry of an unknown write is performed.

Harness `SPIKE-001-table-layout/native_fenced_recovery.py`; raw own statements, terminal statuses, version/readback controls and summary under `out/native/ashlar_fenced_recovery_20261005_r11/`. This is one duplicate race plus sequential/stale controls, not repeated contention admission. The private experimental manifest has the catalog-managed feature; the normative ordinary manifest does not gain this guarantee automatically. Production implementation must guard both graph mutations and publication with the same fence, preserve immutable receipt validation across revocation, and define ownership/lease/privilege rules. Unknown commit responses and network-loss recovery remain untested. A conflict loser requires authoritative revalidation, not blind original-epoch replay.

The observed 3.741s transaction is a single sample and includes fence/manifest work; it is not an isolated marginal overhead estimate or throughput percentile. This overhead must be included in a subsequent integrated ingest clock. Next integrate the fence with graph-data receipt transactions and measure repeated publication/read behavior. Warm caller latency, sustained/burst ingest, 1B-node/5B-edge scale and external graph execution remain open. Goal active; UMF deferred.
